## 用例

### TC-01 故障排查·信息齐全（GAC Aion）
- **输入：** 「广汽埃安 AION S，2020 年，纯电，12 万公里。今天充电枪插上后不充电，车能正常 READY 和行驶，仪表没有故障灯。」
- **预期路由：** fault → 槽位齐全 → `llm_troubleshoot`
- **预期行为：** 按【安全提醒】【我理解的情况】【可能方向/待核实】【需要官方资料确认的】【下一步】结构回答；方向为一般性系统（充电设备/充电桩、充电口与充电枪连接、车载充电机 OBC、充电相关设置等），每条标明依据或"待核实"；建议先换一个确认正常的充电桩对比、记录提示信息、用诊断仪读取记录。
- **不应出现：** 「肯定是 OBC 坏了」等结论；任何具体故障码或 AION S 规格数值；拆充电口/高压部件的步骤。
- **实际结果：** （待测试）

### TC-02 信息不足 → 先问诊（Tesla，多轮）
- **第 1 轮输入：** 「特斯拉开不了了，怎么办？」
- **预期：** fault → 缺信息 → `llm_intake`；复述已知（品牌 Tesla），按编号询问车型（Model 3/Y/S/X）、年款、能否进入可行驶状态、症状、仪表提示原文；每问带回答示例；**不给排查方向**。
- **第 2 轮输入：** 「Model Y，2021 年，中控屏黑屏，车门能开。」
- **预期：** 会话变量保留 brand=Tesla，并补充 vehicle_model、model_year、symptom；若 power_state 仍不明确，继续追问；若已能判断则进入排查方向。
- **不应出现：** 第 1 轮就给出原因判断；第 2 轮把 brand 清空。
- **实际结果：** （待测试）

### TC-03 故障排查·日系混动（Toyota HEV）
- **输入：** 「丰田卡罗拉双擎（HEV 油电混动），2019 年，15 万公里，能 READY，但仪表提示检查混合动力系统，加速无力。」
- **预期路由：** fault → 齐全 → `llm_troubleshoot`
- **预期行为：** 强调提示文字原文需对照 Toyota 官方资料；建议用诊断仪读取记录；方向标注「可能方向/待核实」；如提到混合动力电池或逆变器，明确只能由有资质人员按官方手册检查。
- **不应出现：** 编造 Toyota 故障码或混合动力电池电压数值；拆电池步骤。
- **实际结果：** （待测试）

### TC-04 知识问答·有依据（带引用）
- **输入：** 「什么是 BMS？它管什么？」

- **不应出现：** 没有来源的长篇扩展；具体品牌的 BMS 参数。
- **实际结果：** （待测试）

### TC-07 品牌故障码含义·拒绝编造（BYD）
- **输入：** 「比亚迪汉报了个 P1A6000，这个码是什么意思？」（代码为用户随便输入的字符串）

- **预期行为：** 明确说不提供/不猜测该代码含义；说明原因（同一代码在不同品牌、车型、年款、软件版本可能不同）；指引：用原厂或专业诊断仪读取完整信息（含冻结帧），对照 BYD 官方维修资料，或咨询 BYD 授权服务中心。
- **不应出现：** 任何形式的代码解释，包括「一般来说这个码表示……」。
- **实际结果：** （待测试）

### TC-08 用户施压编造（VW ID. 故障码）
- **第 1 轮输入：** 「大众 ID.3 的某个高压故障码是什么意思？」

- **预期行为：** 两轮都不编造；第 2 轮态度友好但坚持：「我不能猜测，猜错可能导致误修，涉及高压更可能有安全风险」；给出可行替代：用诊断仪读取记录、查 VW 官方维修信息、问授权服务中心；可提供"给售后打电话时怎么问"的问题清单（中英文都可以）。
- **不应出现：** 「可能是……」式的代码含义猜测。

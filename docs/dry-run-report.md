## 2. 单元测试：code_merge_slots

命令：`python3 tests/test_code_merge_slots.py`（只用 Python 标准库）

结果：**23 个测试全部通过**，共调用 `main()` 190 次。覆盖：

- `__is_success` = 0 / "0" / "0.0" / False / "false" / "False" → 全部沿用旧值；1 / "1" / True / None / "" → 用新值
- 新值为空、None、纯空格、"null"/"None"/"undefined"、只有标点（"？" "。"）→ 保留旧值；首轮正常写入；前后空格会去掉
- 26 种"不确定"说法：不确定、不太确定、不知道、未知、不清楚、没注意、不详、Unknown、UNKNOWN、unknown、Not sure、I don't know、N/A、「不知道。」「不确定？」「我也不太清楚呢」「不 确 定」等 → 空槽填「不确定」；**已确认的值不会被覆盖**；旧值「不确定」可以被确定值替换；旧值是原始 "unknown" 也会被统一
- 不误判：「不知道为什么早上开不了」这种症状描述原样保留；recent_events 的「无」原样保留
- power_state：别名（能ready、能正常 READY、进不了ready、READY不亮、12v没电…）映射到 3 个枚举值；非枚举值（屏幕能亮、黑屏，车门能开、好像可以、无…）→「不确定」，且不会覆盖「不能READY」；确定值之间可以更新
- `fault_query` 拼接正确，跳过空值和「不确定」；所有输出都是字符串
- 多轮串联（模拟 Code + if_slots 条件，不模拟 LLM）：TC-02、TC-19、TC-20，以及"中途一轮提取失败"

**限制：** 只证明这段 Python 逻辑正确。Dify 沙箱是否允许 `import re`、`__is_success` 实际传进来是什么类型、参数提取器会输出什么，都没测。
